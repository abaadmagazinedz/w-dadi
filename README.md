# WALID — نسخة عملية كاملة

تطبيق كامل لإدارة التربية البدنية والرياضية:
- لوحة التحكم
- **الأقسام**: إضافة، تعديل الاسم، حذف (مع تلاميذه)، **نسخ قائمة تلاميذ القسم** (كشف جاهز للصق والطباعة)
- **التلاميذ**: إضافة، تعديل، حذف، بحث فوري، **حقل ملاحظات اختياري لكل تلميذ**، عرض **المعدل التلقائي** لكل تلميذ، واستيراد قائمة كاملة دفعة واحدة
- **الحضور والغياب**: تسجيل يومي بحفظ تلقائي فوري، **مع إمكانية اختيار أي تاريخ** (سابق أو لاحق)، ونسخ كشف الحضور اليومي
- **التقييم والنقاط**: إضافة، تعديل، حذف، مرتبطة بالأنشطة الثلاثة السنوية، مع شارة تميّز تلقائية للنقاط ≥16/20
- **الأنشطة**: برنامج الفصول الثلاثة (كرة اليد، كرة السلة، كرة الطائرة)
- **مذكراتي**: مساحة كتابة لكل من البرنامج السنوي، التوزيع السنوي، ومذكرات كل فصل من الفصول الثلاثة على حدة
- **التقارير**: تشمل الآن **كشف معدلات التلاميذ مرتبًا** قابل للنسخ
- الإعدادات
- حفظ محلي دائم على الجهاز (لا إنترنت مطلوب)

## مذكراتي
أيقونة جديدة في الشريط الجانبي تفتح 5 أقسام منفصلة (يتم التنقل بينها بالأزرار في الأعلى): البرنامج السنوي، التوزيع السنوي، ومذكرات كل فصل على حدة. في كل قسم يمكنك:
- **إرفاق ملف Word أو PDF فعلي** من الهاتف (زر "إرفاق ملف")، ثم فتحه لاحقًا بالتطبيق الافتراضي على الهاتف (زر "فتح")، أو استبداله/حذفه في أي وقت.
- **و/أو** كتابة أو لصق ملاحظات نصية إضافية في نفس القسم.
كل شيء محفوظ محليًا على جهازك بشكل دائم بعد الضغط على "حفظ".

## استيراد قائمة التلاميذ
من صفحة "التلاميذ" ← زر "استيراد" — طريقتان:
1. **رفع ملف**: يدعم Excel (.xlsx)، Word (.docx)، أو CSV. العمود/القيمة الأولى = الاسم، ويمكن اختياريًا إضافة القسم ثم الجنس في نفس السطر (مفصولة بفاصلة) لتخصيصها لكل تلميذ على حدة، وإلا يُستخدم القسم الذي تختاره في نافذة الاستيراد.
2. **لصق نصي**: الصق الأسماء مباشرة، اسم في كل سطر — يعمل دائمًا بدون الحاجة لملف.

⚠️ ملاحظة صدق: دعم ملفات Word بسيط ويعتمد على استخراج النص من الفقرات مباشرة — يعمل جيدًا مع قوائم بسيطة (اسم في كل سطر/فقرة)، لكن الأعمدة والجداول المعقدة داخل Word قد لا تُقرأ بدقة. **الأنسب عمليًا هو Excel أو CSV** لأنهما أدق وأكثر استقرارًا لهذا النوع من البيانات.

## الكشوف القابلة للطباعة
بدل تصدير PDF (يتطلب مكتبات إضافية لم أرغب بإضافتها لتقليل المخاطر)، أضفت أزرار **"نسخ"** في الأقسام والحضور والتقارير — تنسخ الكشف كنص منسّق إلى الحافظة، يمكنك لصقه مباشرة في Word أو أي تطبيق ملاحظات ثم طباعته من هناك.

## إصلاحات مؤكدة (من سجلات بناء حقيقية فشلت على GitHub Actions)
هذه الأخطاء اكتُشفت من سجلات بناء حقيقية أرسلتها لي (وليس فقط من قراءة الكود)، وتم إصلاحها بدقة:
1. **`TextDirection.rtl` غير موجود**: مكتبة `intl` تُعرّف نوعها الخاص باسم `TextDirection` يتعارض مع نوع Flutter الأصلي. الحل: `import 'package:intl/intl.dart' hide TextDirection;`.
2. **`_AttendanceRow` لا يقبل `key`**: كان الكلاس ناقصًا `super.key` في الباني (constructor) رغم تمرير `key:` عند استخدامه. تمت الإضافة.
3. **تعارض compileSdk مع `file_picker`**: نسخة `file_picker` القديمة (8.x) كانت تتطلب compileSdk أقدم مما تحتاجه مكتباتها الداخلية. تم الترقية إلى `file_picker: ^10.0.0`.
4. **`readAsBytes` غير موجود على `PlatformFile`**: افترضت خطأً وجود هذه الدالة بناءً على وصف نصي في سجل تغييرات المكتبة، لكن سجل بناء حقيقي أثبت عدم وجودها في النسخة المثبتة فعليًا. الحل: العودة لاستخدام `withData: true` مع الخاصية `file.bytes` مباشرة (وهي الطريقة المضمونة والمثبتة).
5. **عنوان الصفحة يظهر حرفًا حرفًا بشكل عمودي** (لوحظ من لقطات شاشة فعلية من التطبيق، في صفحتي "التلاميذ" و"الحضور"): كان عنوان الصفحة وزرّان يتشاركان نفس السطر، فإذا ضاقت المساحة (خصوصًا مع وجود زر إضافي مثل "استيراد" أو "نسخ الكشف")، ينضغط العنوان إلى عرض شبه معدوم فيلتف حرفًا حرفًا. الحل: أصبح العنوان دائمًا في سطر مستقل بعرض كامل، والأزرار في سطر منفصل تحته يلتف تلقائيًا عند الحاجة (Wrap) بدل أن يضغط العنوان.

5. **عنوان الصفحة يظهر حرفًا حرفًا بشكل عمودي** (لوحظ من لقطات شاشة فعلية من التطبيق، في صفحتي "التلاميذ" و"الحضور"): كان عنوان الصفحة وزرّان يتشاركان نفس السطر، فإذا ضاقت المساحة (خصوصًا مع وجود زر إضافي مثل "استيراد" أو "نسخ الكشف")، ينضغط العنوان إلى عرض شبه معدوم فيلتف حرفًا حرفًا. الحل: أصبح العنوان دائمًا في سطر مستقل بعرض كامل، والأزرار في سطر منفصل تحته يلتف تلقائيًا عند الحاجة (Wrap) بدل أن يضغط العنوان.
6. **أزرار "الوصول السريع" في لوحة التحكم لا تعمل إطلاقًا**: كانت هذه الأزرار (إضافة تلميذ، تسجيل الحضور، إدخال تقييم، إنشاء تقرير) مجرد بطاقات مزخرفة بدون أي إجراء فعلي عند الضغط عليها — خطأ حقيقي مني. الآن كل زر ينقلك مباشرة للصفحة المطلوبة.
7. **قائمة التلاميذ كانت تعرض كل التلاميذ مجمّعين معًا دون تمييز بين الأقسام**: أضفت أزرار تصفية بالأقسام في أعلى صفحة "التلاميذ" ("الكل" + كل قسم على حدة)، وعند اختيار "الكل" يظهر التلاميذ مجمّعين تحت عنوان كل قسم بشكل واضح ومنفصل، بدل قائمة واحدة مبعثرة.
8. **الاستيراد كان يُنشئ "قسمًا" وهميًا لكل تلميذ**: إذا كان اسم التلميذ يحتوي على فاصلة (شائع في التنسيق "اللقب، الاسم")، كان الاستيراد يُفسّر الجزء الذي بعد الفاصلة على أنه اسم قسم جديد، فيمتلئ سجل الأقسام بأسماء تلاميذ بدل أقسام حقيقية. الحل: أصبح الاستيراد الآن يأخذ السطر/الخلية بأكملها كاسم التلميذ دائمًا، ويُدخل الجميع مباشرة في القسم الذي تختاره في نافذة الاستيراد فقط، دون أي تخمين لعمود قسم إضافي.

**⚠️ إذا كنت قد استوردت بيانات من قبل هذا الإصلاح:** على الأرجح تراكمت عندك "أقسام" وهمية في صفحة "الأقسام" (أسماء تلاميذ ظهرت هناك بالخطأ). لتنظيفها: احذفها يدويًا من صفحة "الأقسام" (⋮ ← حذف)، أو إن كانت كثيرة جدًا، استخدم "الإعدادات ← مسح جميع البيانات" للبدء من جديد ثم أعد الاستيراد بعد التحديث.

## التشغيل محليًا (اختياري، لمن يملك جهاز حاسوب)
1. ثبّت Flutter حديثًا.
2. أنشئ مشروعًا: `flutter create walid`
3. استبدل `pubspec.yaml` و`lib/main.dart`.
4. نفّذ `flutter pub get`
5. نفّذ `flutter run`

## Supabase
يوجد ملف `supabase_schema.sql` يحتوي مخطط قاعدة البيانات.
لم يتم تضمين URL أو anon key حقيقيين، لأن هذه بيانات مشروعك الخاصة. النسخة الحالية تعمل محليًا فقط؛ الربط بـ Supabase غير مفعّل بعد.

## بناء ملف APK تلقائيًا وتنزيله عبر GitHub
هذا المشروع يحتوي على ملف `.github/workflows/build-apk.yml` يقوم ببناء ملف APK تلقائيًا في كل مرة ترفع فيها الكود، وينشره كـ Release قابل للتنزيل مباشرة من الهاتف.

خطوات الاستخدام:
1. أنشئ مستودع (repository) جديد على GitHub، باسم مثلاً `walid-app`.
2. ارفع محتوى هذا المجلد بالكامل (بما فيه مجلدَي `.github` و`keystore`) إلى المستودع — إما بالسحب والإفلات عبر واجهة GitHub في المتصفح (زر "Add file" ثم "Upload files")، أو عبر git من الحاسوب:
   ```
   git init
   git add .
   git commit -m "نسخة عملية"
   git branch -M main
   git remote add origin https://github.com/USERNAME/walid-app.git
   git push -u origin main
   ```
3. بمجرد الرفع، يبدأ GitHub تلقائيًا ببناء التطبيق (تبويب "Actions"، تستغرق العملية 3-5 دقائق).
4. بعد اكتمال البناء، اذهب إلى تبويب "Releases" — ستجد ملف `WALID.apk` جاهزًا للتنزيل مباشرة على هاتفك (فعّل "تثبيت من مصادر غير معروفة" عند التثبيت أول مرة).
5. أي تعديل لاحق على الكود ورفعه إلى فرع `main` سينشئ تلقائيًا نسخة APK جديدة، وستُثبَّت فوق النسخة السابقة مباشرة بدون أي مشاكل (رقم الإصدار يزداد تلقائيًا مع كل بناء).

يمكنك أيضًا تشغيل البناء يدويًا في أي وقت من تبويب Actions عبر زر "Run workflow".

### مهم: عند أول تثبيت لهذه النسخة
إذا كان عندك أي نسخة سابقة من WALID مثبّتة (من قبل إضافة مفتاح التوقيع الثابت)، احذفها يدويًا **مرة واحدة فقط**:
1. الإعدادات ← التطبيقات ← ابحث عن WALID ← Uninstall.
2. ثبّت أحدث ملف APK من تبويب Releases بشكل طبيعي.
بعد هذه المرة، كل التحديثات القادمة ستُثبَّت فوق بعضها تلقائيًا بدون أي حاجة للحذف.
